القرار المختصر

ماذا نبني؟

  • API باسم POST /v1/classify.
  • محرك بحث ذكي: حرفي، إملائي، ودلالي.
  • واجهة تجريبية بسيطة لعرض النتيجة للفريق.
  • إرجاع root_good_type_id مع سبب وراية مراجعة.

ماذا لا نبني؟

  • لا مطابقة منتج بعينه.
  • لا Agent في نسخة الـMVP.
  • لا بحث إنترنت في الطلب المباشر.
  • لا Vector Database حالياً.

آلية العمل

  1. النص

    يدخل السائق أي وصف عربي، إنجليزي، مختلط، أو لغة أخرى.

  2. التطبيع

    تنظيف محافظ للنص بدون تغيير النص الأصلي.

  3. الحرفي

    بحث في أسماء الجذور والأبناء والأسماء الشائعة.

  4. الإملائي

    التقاط الأخطاء مثل مواد غزائيه أو كيتكات.

  5. الدلالي

    Embedding محلي لفهم المعنى واللهجات.

  6. القرار

    تجميع النتيجة على الصنف الرئيسي وإرجاع مراجعة عند الغموض.

حالات القرار

EXACT

تطابق واضح مع صنف رئيسي واحد.

HYBRID_STRONG

البحث الإملائي والدلالي متفقان.

AMBIGUOUS

أكثر من صنف قريب، لذلك نرفع راية مراجعة.

LOW_EVIDENCE

براند أو نص غير واضح ولا يجوز الثقة به آلياً.

خطة التنفيذ

  1. 1

    تأسيس الخدمة

    FastAPI، API key، schemas، health check، وواجهة demo.

  2. 2

    استيراد الكتالوج

    قراءة good_types، استخراج الجذور، وتحويل aliases إلى الجذر.

  3. 3

    البحث الذكي

    Exact + Fuzzy + Semantic embeddings داخل الذاكرة.

  4. 4

    سياسة القرار

    Top 1، بدائل، وrequiresReview عند الغموض أو اللغة غير المدعومة.

  5. 5

    الاختبار والربط

    اختبارات API، قياس latency، وتوثيق استدعاء زر إضافة جديد.

بعد الـMVP

  • بناء gold dataset من قرارات دندن الفعلية.
  • إضافة قاموس براندات وaliases معتمدة.
  • إضافة reranker فقط إذا أثبتت البيانات الحاجة.
  • إدخال Agent إداري لاحقاً للحالات الصعبة، خارج مسار الطلب المباشر.
هذه النسخة تلغي افتراض مطابقة المنتج أو الفئة الفرعية. معيار النجاح هو إرجاع صنف رئيسي صحيح، سريع، وقابل للمراجعة عند الغموض.
